# PRD 0003 — Command line interface

## Problem
FlareSync is configured and operated exclusively from the command line, usually over SSH on a headless Linux host.

## Goals
- A single executable, `flaresync`, acting both as CLI and as service.
- Every configuration change is possible through commands; editing JSON by hand is never required.

## Functional requirements
- **FR-200** The configuration directory defaults to `config/` next to the executable. It can be overridden with the
  global `--config-dir` option or the `FLARESYNC_CONFIG_DIR` environment variable.
- **FR-201** Commands:

  | Command | Purpose |
  |---|---|
  | `init` | Create the configuration directory, default `flaresync.json`, and the master key |
  | `run` | Service mode |
  | `sync [--force]` | Run one sync cycle and exit |
  | `ip` | Show the detected public addresses and which source answered |
  | `status` | Show every record of every provider with last applied address and time |
  | `ip-source list \| add <url> --family ipv4\|ipv6 [--position N] [--json-field F] \| remove <url>` | Manage IP sources |
  | `dns list \| add <server[:port]> \| remove <server> \| clear \| test [host]` | Manage custom DNS for IP sources |
  | `interval [value]` | Show or set the service interval |
  | `<provider> ...` | Provider-specific commands, e.g. `cloudflare login` |

- **FR-202** Secrets typed interactively are not echoed.
- **FR-203** Exit code is `0` on success and non-zero on failure.
- **FR-204** Configuration files are written atomically and, on Unix, with mode `600`.

## Non-functional requirements
- **NFR-200** All help texts, prompts, and messages are in English.
- **NFR-201** The CLI works in non-interactive environments; commands that need input fail with a clear message
  unless the value is passed as an option.
